# 高数作业助手 · 设计文档（增强版）

> 本文档在既有架构基础上，补齐四类教学管理增强能力与两项识别精度优化，
> 并说明 §5.1 这类"无答案且无裁切图"章节的脚本化导入方案（Route 2）。

## 1. 系统架构

三层职责分离，模型结果仅作候选，涉及成绩发布时必须保留证据与教师复核入口。

| 层 | 端口 | 职责 | 关键组件 |
|----|------|------|----------|
| 工作台（证据库）| 8014 | 教材/答案原始证据、题目与裁切图权威库 | `api_app.vision.py`、`POST /ingest/book`、`POST /problems`、`PUT /problems/{pid}/answer`、`answer_import_candidates` |
| 智能体（教师端）| 8000 | 组卷、收作业、批改编排、复核与报表 | `app/main.py`、`grading_pipeline.py`、`knowledge_bridge.py`、`db.py`(homework.db) |
| 视觉模型（VLM）| 18080 | 题图转写、独立求解、手写阅卷 | `server_vlm_service.py`： `/solve-from-image`、`/solve`、`/grade-homework` |

数据流向：`8014(证据) ──sync──> 8000(本地缓存)`；`学生PDF ──8000──> VLM阅卷 ──> 8000证据+复核 ──> 成绩`。

## 2. 设计文档增强（四类教学管理能力）

### 2.1 人工复核配额（每班不少于 2 次）
- **规则**：每个班级（按 `semester` 维度）累计的"教师已裁定复核"次数必须 ≥ `REVIEW_QUOTA_PER_CLASS = 2`。
- **实现**：`grading_experiences` 仅在教师 `POST /api/submissions/{id}/review` 裁定时写入，故其去重计数即教师复核次数。
- **端点**：`GET /api/reports/review-quota` 返回每个班级/学期的 `teacher_reviews`、`quota`、`meets_quota`，并汇总 `classes_below_quota`。
- **总览**：`GET /api/reports/summary` 新增 `classes_below_review_quota`、`review_quota_per_class`。
- **策略**：低于配额的班级在教师门户持续提示，避免"全自动出分"而缺乏人工把关。

### 2.2 薄弱知识点建议
- **数据**：`questions.knowledge_points`（无标签时回退 `chapter`）作为知识点维度；逐题得分来自 `grading_experiences.evidence_json.results`。
- **聚合**：按知识点汇总 `得分率 = Σ学生得分 / Σ题目满分`，`avg_rate < 0.7` 标记为薄弱并给建议"加强练习与错题重做"。
- **端点**：`GET /api/reports/weak-points?class_name=&semester=&top=` 返回排序后的薄弱点列表（得分率升序）。

### 2.3 学期末分数汇总统计
- **维度**：`assignments.semester` + `class_name`。仅在 `submissions.status='graded'` 上聚合。
- **指标**：每生总分/平均分/得分率/排名；班级均分、分数段分布（优秀≥90 / 良好≥75 / 及格≥60 / 不及格<60）、书写整洁度均值。
- **端点**：`GET /api/reports/semester-summary?class_name=&semester=`。

### 2.4 书写整洁度评估维度
- **采集**：VLM `/grade-homework` 在阅卷时对每个题评分 `handwriting_score`（0–100）与 `handwriting_note`；Agent 端 `grading_pipeline.py` 汇总为提交级 `submissions.handwriting_score`（各题均值）。
- **呈现**：学期汇总按生/班给出 `handwriting_avg`；教师可在复核页看到逐题整洁度，作为过程性评价依据（不参与客观分，仅作维度参考）。

## 3. 识别精度优化（两项）

### 3.1 题号精确定位（`/grade-homework`）
- **问题**：3B 模型在整份多页手写作业中有时把相邻题的作答误判为当前题。
- **方案（两段式）**：
  1. **定位段（Locator）**：一次轻量调用，让模型把每个 `problem_no` 映射到出现的图片页序号，并摘录题干片段。
  2. **阅卷段**：每题限定在定位到的页，并要求模型回显 `located_problem_no` 与 `located_problem_text`；段末强制自检。
- **兜底**：若回显题号与请求题号不一致或为空，强制 `need_review=True` 并写入风险"题号定位可能错配"，绝不让错配分数静默通过。

### 3.2 标准答案二次校验（`knowledge_bridge.build_image_solve_candidate`）
- **目标**：确保导入 8014 的标准答案准确、一致，避免答案书 OCR 瑕疵或 VLM 单次误读被直接采信。
- **机制（按可用通道择一，绝不因缺通道而放松）**：
  1. **题干可读** → 调 VLM `/solve`（独立纯文本求解），与答案书答案做符号判等；不一致即"二次校验未通过"。
  2. **题干缺失** → 对**同一裁切图**做第二次 `/solve-from-image` 读取，两次视觉答案必须一致（符号判等或宽松归一一致）。
- **后果**：即便双模型一致性门禁通过，若二次校验未过，候选从 `eligible` 降为 `pending_review`，附风险说明，等教师裁定。返回结构新增 `verification` 字段便于追溯。

## 4. Route 2 脚本化导入（§5.1 等无答案且无裁切图章节）

- **现状**：`extract_img/book/` 仅有 1.1–4.7；§5.1 既无答案也无裁切图。
- **工具**：`route2_chapter_importer.py` + `ROUTE2_IMPORT_GUIDE.md` + `route2_input/5.1/` 脚手架。
- **管道**：`crops/*.png`（每图一题）+ 可选 `manifest.json`（人工答案/知识点覆盖）→ VLM `/solve-from-image` 转写+独立求解 → 生成 8014 `POST /ingest/book` 所需 `book_problems.json` → `--push` 写入本地 8014 证据库（含源图证据）。
- **质量保障**：缺答案的题标记为 `unverified`（待人工复核），不以猜测值发布；源裁切图保留于 `answer_source_previews/route2/<章节>/` 供教师溯源。
- **重要**：脚本**不伪造数学内容**，教材原页与对应答案须由教师/助教提供。

## 5. 数据安全与一致性
- 所有写回 8014 的答案都经教师确认；Agent 本地库（homework.db）仅为工作缓存，8014 为权威。
- 成绩证据（`grading_experiences`）只来自教师裁定，可作为可复用经验沉淀。
- 新增字段均通过幂等 `ALTER TABLE` 迁移（`db.py init_db`），不影响既有数据。
