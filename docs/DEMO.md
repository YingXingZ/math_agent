# 90 秒演示与可复现 Demo

目标是让面试官在 90 秒内看到：这不是“模型随便打分”，而是一套能解释、能失败、可人工接管的 Agent Harness。

## 演示前准备

1. 按根目录 [README](../README.md#快速开始) 启动 API；完整自动批改另需启动 Redis、VLM 和 8014。
2. 使用教师账号登录，调用 `POST /api/admin/demo-package` 创建隔离的演示班级、作业和样例答案图。
3. 只使用 `DEMO` 班级/账号进行展示。它不会计入正式教学报表，结束后可调用 `DELETE /api/demo/submissions` 清理演示提交。
4. 打开教师工作台、学生提交页、一次已完成的教师复核和 Agent Trace 报告页；不要在演示中展示真实学生信息。

## 讲解脚本

| 时间 | 操作 | 讲述重点 |
| --- | --- | --- |
| 0–10 秒 | 打开工作台 | “这是可验证 AI Agent 工作台；高数批改只是我选择的高风险真实场景。” |
| 10–25 秒 | 展示作业题目与原题小问 | “作业记录原始题号和抽取的小问；批改从 PDF 的实际题目区域开始，而不是整页 OCR。” |
| 25–45 秒 | 打开一题初评证据 | “先由 SymPy 做确定性核验；不充分时，模型在不读取标准答案的条件下独立求解，再交叉验证。” |
| 45–60 秒 | 展示缺答、低置信或冲突题 | “缺少小问、解析失败、模型冲突不会给满分；系统明确转给教师，而不是用置信度掩盖不确定性。” |
| 60–75 秒 | 打开 Trace / 教师裁定 | “每个路线保留工具、版本、耗时、错误码与裁定证据，老师可以逐题修正后发布。” |
| 75–90 秒 | 打开 CI / 评测文档 | “固定评测覆盖正确、错误、空白、部分完成和等价写法；每次变更都会跑回归门禁。” |

## 故障演示（可选，15 秒）

在隔离环境中令 VLM 返回超时、5xx 或类型错误的 JSON。预期行为不是 HTTP 500 或伪造分数，而是：记录标准化错误/风险原因、分数与置信度安全降级，并把题目放入教师复核。不要在真实教学任务运行时人为中断服务。

## 演示结束核对

- 确认演示账号与提交均为 `DEMO` 范围。
- 确认工作台未显示真实学生姓名、学号、上传原件或密钥。
- 若录屏上传到公开平台，先检查浏览器地址、终端环境变量与 Trace 内容。
