问题3：目前最大的技术挑战和工程风险是什么？

第一风险：数学 OCR，而不是 Agent

普通文字 OCR：

系统完全不会报编码错误，却会直接导致答案错误。
所以不要只设置：

+
confidence
+

+

第二风险：你现在的“乱码”问题必须先查清
特别注意：
如果“只有筛选后打开某些题目才乱码”，我反而不首先怀疑 PDF 编码。
更可能是：
数据库内容
↓
API序列化
↓
前端渲染
某一条路径发生问题。
建议你直接选一个出现乱码的题目，比如：

然后按下面顺序检查：

                ↓
② FastAPI 返回的 JSON 正常吗？
                ↓
③ 浏览器 F12 → Network → Response 正常吗？
                ↓
④ 页面 DOM 里的内容正常吗？
结果可以立刻定位。
情况 A
数据库正常：
∫ sin x dx
API 正常：
∫ sin x dx
网页乱码：
前端渲染问题。

情况 B
数据库正常，但是 API：
æ°å¦
这是：
UTF-8/编码问题。

情况 C
数据库里面已经：

那根本不是乱码。
这是：
OCR / PDF解析结果已经坏了。

情况 D
中文正常：
求下列函数极限
只有数学公式乱：
大概率不是 UTF-8，而是 PDF 字体映射、公式解析、OCR 或 LaTeX 转换的问题。
所以：
“乱码”和“OCR错误”一定要拆开排查。

↓

↓

↓

↓

也就是说：
